GOLDBERG SEARCH REFACTOR TASKS
================================

1. Data Model Consolidation (Target & Person)
   Change: Replace parallel Vecs (first_names_list, last_names_list, address_list) with:
           Person { first_name, last_name, address, raw_name }
           Target { target_identifier, entries: Vec<Person> }
   Why: Prevent index misalignment bugs, easier extension (add phone/email later), cleaner semantics.
   File: src/target.rs
   Replace: existing `pub struct Target { first_names_list: Vec<String>, last_names_list: Vec<String>, address_list: Vec<String>, }`
   With: `#[derive(...)] pub struct Person { ... }` then `#[derive(...)] pub struct Target { pub target_identifier: String, pub entries: Vec<Person>, }`
   Lines: Around the first struct definitions (search for `pub struct Target {`).

2. Derive Traits on Models
   Change: #[derive(Serialize, Deserialize, Debug, Clone, Default)] on Person and Target.
   Why: Enables JSON persistence, debugging, cloning for tests, and easy initialization.
   File: src/target.rs
   Add: `#[derive(Serialize, Deserialize, Debug, Clone, Default)]` above both structs.
   Requires: Ensure `use serde::{Serialize, Deserialize};` at top.

3. Constructor Method
   Change: Implement Target::new<I: Into<String>>(identifier: I).
   Why: Centralizes initialization; avoids manual field population; accepts &str or String.
   File: src/target.rs
   Add inside impl Target: `pub fn new<I: Into<String>>(id: I) -> Self { Self { target_identifier: id.into(), entries: Vec::new() } }`
   Remove: Any manual constructions in main.rs populating now-removed Vec fields.

4. Mutating add_parcel Method
   Change: pub fn add_parcel(&mut self, parcel: &Value).
   Why: Avoids consuming self each call; allows repeated accumulation without reassigning.
   File: src/target.rs
   Replace: `trait AddParcel { fn add_parcel(self, parcel: &Value) -> Target; }` and its impl.
   With: `pub trait Expandable { fn add_parcel(&mut self, parcel: &Value); }` and impl mutably pushing Person to entries.
   Update main.rs import: `use target::{Target, Expandable};` (search old AddParcel usage).

5. Name Parsing Improvements
   Change: Use split_whitespace and safe indexing with length checks.
   Why: Handles extra spaces and single-token names; reduces panic risk.
   File: src/target.rs add_parcel impl.
   Replace: `let name_seperated: Vec<&str> = name.trim().split(" ").collect();` with `let parts: Vec<&str> = raw_name.split_whitespace().collect();` and conditional length logic.

6. Raw Name Preservation
   Change: Store raw_name in Person.
   Why: Retains original formatting for later heuristic refinement / auditing.
   File: src/target.rs
   Add field: `pub raw_name: String,` to Person; set in add_parcel: `raw_name: raw_name.to_string(),`.

7. Safe JSON Field Extraction
   Change: Use as_str().unwrap_or("").trim() instead of to_string().
   Why: Avoids adding quotes and handles missing/null gracefully.
   File: src/target.rs add_parcel.
   Replace: `parcel["attributes"]["MAILING_NAME"].to_string()` with `parcel["attributes"]["MAILING_NAME"].as_str().unwrap_or("").trim()` (assign to raw_name variable).

8. Single Source Entry Storage
   Change: Push a Person instance instead of three separate pushes.
   Why: Atomic addition; reduces risk of partial state on error.
   File: src/target.rs
   Replace three pushes to separate Vecs with one `self.entries.push(Person { ... });`.

9. Duplicate Entry Handling
   Change: Implement Target::dedup() using HashSet of (first,last,address).
   Why: Prevents redundant accumulation across pages or repeated selections.
   File: src/target.rs
   Add: method `pub fn dedup(&mut self) { use std::collections::HashSet; let mut seen=HashSet::new(); self.entries.retain(|p| seen.insert((p.first_name.clone(), p.last_name.clone(), p.address.clone()))); }`
